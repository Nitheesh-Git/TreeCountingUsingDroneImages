# Comparison models: YOLOv9t and YOLOv12n

This folder holds additional literature-survey models. They are compared against the
project's reference models, **YOLOv8n** (`train.py`) and **YOLO11n** (`src/train_yolov11.py`).
The reference models, their scripts and their outputs are not modified or retrained here.

> **Read before comparing numbers.** YOLOv8n and YOLO11n were trained on the **full
> 1,191-image** training split. YOLOv9t and YOLOv12n are trained on a **594-image half
> subset**, on a **different machine**, with a **30-minute CPU training budget each** (both
> models trained at the same time, about 17 of 30 epochs). This was a deadline constraint. Any difference in metrics therefore mixes architecture, training-data size
> and implementation effects. This experiment **does not isolate architecture alone**.

## Training-data protocol

Generated by `python comparison_models/common/make_subset.py` (seed 0, fraction 0.5):

1. **Group-level selection.** The Roboflow export augmented each training source image into
   3 versions, so the 1,191 images are 375 source-name groups. Groups are sampled whole.
   Sampling single files would keep about 87% of the unique scenes, which is not a real
   halving of the data.
2. **Leakage precaution.** 10 training groups share a source name with a valid or test
   image. Pixel comparison suggests some may be the same scene. They are excluded from the
   subset. The original splits are left unchanged, and the baselines did train on these
   images.
3. **Stratified by NEON site** (ABBY, BART, …). Groups are shuffled with a fixed seed, and
   each site gets about half its original count. A seeded top-up pass then brings the
   total to **594 images (188 groups, 5,190 tree instances)**.
4. Instances per image, box-size quantiles and the small/medium/large box shares match the
   full split closely (see `common/subset_stats.md`). All labels in all three splits are
   valid YOLO format, class 0 only, with 0 orphans.
5. Training reads the subset through `comparison_models/data/tree_top_view_half/`. This is
   a per-file symlink view, which falls back to copies where symlinks are unavailable. Its
   `data.yaml` points at the original **unchanged** 116-image valid and 55-image test
   splits. The original dataset and `data.yaml` are only read. Ultralytics' label caches
   are written inside the view, not into `datasets/`.

## Implementations and weights

| Model | Implementation used | Upstream | Pretrained checkpoint |
|---|---|---|---|
| YOLOv9t | Ultralytics `ultralytics==8.4.177` | WongKinYiu/yolov9 (official) | `yolov9t.pt`, Ultralytics assets v8.3.0, COCO |
| YOLOv12n | Ultralytics `ultralytics==8.4.177` | sunsmarterjie/yolov12 (official) | `yolo12n.pt`, Ultralytics assets v8.3.0, COCO |

Both run through the same Ultralytics trainer as the YOLOv8n and YOLO11n baselines. They
share the same data loader, augmentation pipeline, loss, optimizer selection and metric
code, which makes them the fairest comparison available. Neither checkpoint is a
substitute variant: `yolov9t` is the YOLOv9 tiny model, and `yolo12n` is the YOLO12 nano
model. The upstream repos have their own trainers, which differ in augmentation,
schedules and dual-branch auxiliary heads for YOLOv9. They also ship newer weight
releases, for example the YOLOv12 "turbo" checkpoints. Those are not used here.

## Settings

| Setting | YOLOv8n / YOLO11n (reference) | YOLOv9t / YOLOv12n |
|---|---|---|
| Training images | 1,191 (full split) | **594 (half subset)** |
| Image size | 416 | 416 |
| Max epochs / patience | 30 / 5 | 30 / 5 |
| Batch | 8 | 8 |
| Seed | default (v8n), 0 (v11n) | 0 |
| Optimizer | `auto` → AdamW (lr 0.002) | `auto` → AdamW (lr 0.002)* |
| Augmentation | Ultralytics defaults, mosaic closed at last 10 epochs | same |
| Training device | CPU (Intel i7-1255U), one run at a time | **CPU (Intel i5-12500H), both runs at the same time, 8 threads each** |
| Training length | up to 30 epochs (about 2.2–2.4 h) | **0.5 h time budget (`--time 0.5`), 17 epochs, LR schedule fitted to the budget** |
| Latency measured on | CPU (i7-1255U) | CPU (Intel i5-12500H) |

\* Ultralytics `optimizer=auto` chooses AdamW when the run is under 10k iterations. The
subset run is 30 × 75 = 2,250 iterations and the full run is 30 × 149 = 4,470, so both get
AdamW. The actual choice is logged in each run's `args.yaml` and the training log.

**Latency.** Latency uses the same protocol as `docs/yolov8n_vs_yolo11n_comparison.md`: 30
test images × 3 passes after warm-up, batch 1, 416 px, CPU. The new models are measured
on a different CPU from the baselines, so absolute milliseconds are **not** directly
comparable across the two machines. Compare YOLOv9t against YOLOv12n directly, and
compare them with the baselines only in relative terms.

**Test-set status.** The 55-image test split has already been evaluated several times
for YOLOv8n and YOLO11n. For the new models, checkpoint selection and any decisions use
the validation split only. The test split is evaluated once, after training is final.

## Commands

```bash
python comparison_models/common/make_subset.py                 # (re)generate subset, deterministic
python comparison_models/yolov9/train.py --time 0.5            # train (CPU, as run here); --resume to continue
python comparison_models/yolov9/evaluate.py --split val        # validation metrics + counting + CPU latency
python comparison_models/yolov9/evaluate.py --split test       # final test evaluation (once)
python comparison_models/yolov9/predict.py path/to/image.jpg   # count trees in an image or folder
```

Replace `yolov9` with `yolov12` for the other model.
