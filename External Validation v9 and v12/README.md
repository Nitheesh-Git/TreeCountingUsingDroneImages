# Comparison models: YOLOv9t and YOLOv12n

This folder holds two literature-survey models, YOLOv9t and YOLOv12n, trained and evaluated
on the Tree-Top-View dataset under identical conditions. The project's existing scripts,
models and outputs are not modified here.

> **Training setup.** Both models are trained on a **594-image half subset** of the training
> split, with a **30-minute CPU training budget each** (both trained at the same time, 17
> epochs). This was a deadline constraint. Evaluation uses the original, unchanged validation
> and test splits.

## Training-data protocol

Generated by `python "External Validation v9 and v12/common/make_subset.py`" (seed 0, fraction 0.5):

1. **Group-level selection.** The Roboflow export augmented each training source image into
   3 versions, so the 1,191 images are 375 source-name groups. Groups are sampled whole.
   Sampling single files would keep about 87% of the unique scenes, which is not a real
   halving of the data.
2. **Leakage precaution.** 10 training groups share a source name with a valid or test
   image. Pixel comparison suggests some may be the same scene. They are excluded from the
   subset. The original splits are left unchanged.
3. **Stratified by NEON site** (ABBY, BART, …). Groups are shuffled with a fixed seed, and
   each site gets about half its original count. A seeded top-up pass then brings the
   total to **594 images (188 groups, 5,190 tree instances)**.
4. Instances per image, box-size quantiles and the small/medium/large box shares match the
   full split closely (see `common/subset_stats.md`). All labels in all three splits are
   valid YOLO format, class 0 only, with 0 orphans.
5. Training reads the subset through `External Validation v9 and v12/data/tree_top_view_half/`. This is
   a per-file symlink view, which falls back to copies where symlinks are unavailable. Its
   `data.yaml` points at the original **unchanged** 116-image valid and 55-image test
   splits. The original dataset and `data.yaml` are only read. Ultralytics' label caches
   are written inside the view, not into `datasets/`.

## Implementations and weights

| Model | Implementation used | Upstream | Pretrained checkpoint |
|---|---|---|---|
| YOLOv9t | Ultralytics `ultralytics==8.4.177` | WongKinYiu/yolov9 (official) | `yolov9t.pt`, Ultralytics assets v8.3.0, COCO |
| YOLOv12n | Ultralytics `ultralytics==8.4.177` | sunsmarterjie/yolov12 (official) | `yolo12n.pt`, Ultralytics assets v8.3.0, COCO |

Both run through the same Ultralytics trainer, so they share the same data loader,
augmentation pipeline, loss, optimizer selection and metric code. Only the architecture differs. Neither checkpoint is a
substitute variant: `yolov9t` is the YOLOv9 tiny model, and `yolo12n` is the YOLO12 nano
model. The upstream repos have their own trainers, which differ in augmentation,
schedules and dual-branch auxiliary heads for YOLOv9. They also ship newer weight
releases, for example the YOLOv12 "turbo" checkpoints. Those are not used here.

## Settings

| Setting | YOLOv9t / YOLOv12n |
|---|---|
| Training images | 594 (half subset) |
| Image size | 416 |
| Max epochs / patience | 30 / 5, overridden by the time budget |
| Training length | 0.5 h time budget (`--time 0.5`), 17 epochs, LR schedule fitted to the budget |
| Batch | 8 |
| Seed | 0 |
| Optimizer | `auto` → AdamW (lr 0.002)* |
| Augmentation | Ultralytics defaults; `close_mosaic=10` (mosaic off from epoch 9 / 8 under the budget) |
| Training device | CPU (Intel i5-12500H), both runs at the same time, 8 threads each |
| Latency measured on | CPU (Intel i5-12500H), no other job running |

\* Ultralytics `optimizer=auto` chooses AdamW when the run is under 10k iterations (the subset run is
at most 30 × 75 = 2,250). The actual choice is logged in each run's `args.yaml` and the training log.

**Latency.** 30 test images × 3 passes after warm-up, batch 1, 416 px, CPU. Absolute milliseconds
depend on the machine; the two models were timed on the same one.

**Test-set status.** Checkpoint selection and any decisions use the validation split only. The test
split is evaluated once per model, after training is final.

## Commands

```bash
python "External Validation v9 and v12/common/make_subset.py"                 # (re)generate subset, deterministic
python "External Validation v9 and v12/yolov9/train.py" --time 0.5            # train (CPU, as run here); --resume to continue
python "External Validation v9 and v12/yolov9/evaluate.py" --split val        # validation metrics + counting + CPU latency
python "External Validation v9 and v12/yolov9/evaluate.py" --split test       # final test evaluation (once)
python "External Validation v9 and v12/yolov9/predict.py" path/to/image.jpg   # count trees in an image or folder
```

Replace `yolov9` with `yolov12` for the other model.
